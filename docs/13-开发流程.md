# 开发流程

每个可交付功能遵循：

1. 阅读 `docs`，确认 PRD、ADR、数据、API 与边界；有架构影响先提出 ADR。
2. 在 `14-TODO` 记录范围、验收条件、依赖和风险，拆分为一个可测试模块。
3. 先定义领域模型、接口/Schema 和测试案例，再实现后端、前端或任务适配。
4. 本地执行格式化、静态检查、单元及相关集成测试；手工走通主路径和失败路径。
5. 更新迁移、OpenAPI、Prompt/评分版本、文档和 TODO 历史；记录已知限制。
6. 评审时检查数据来源许可、隐私、可观测性、降级和向后兼容性。

不得在一个变更中夹带无关重构。第三方依赖、新模型、数据源、外部 API 与数据库破坏性变更均需说明理由、版本、回滚/降级方式。完成定义（DoD）：代码、测试、文档、配置示例和验收证据齐全。

## 标准开发流程

每个功能都应按以下顺序完成：

1. 先理解需求与边界：阅读 PRD、ADR、数据字典与相关规范，确认是否涉及架构变化。
2. 先定义验收条件：明确“输入、输出、失败场景、成功场景”和可验证证据。
3. 先定义接口与数据结构：先编写 Schema、迁移草案、测试用例，再开始实现。
4. 再实现核心逻辑：领域逻辑优先写成可测试的服务或纯函数，避免把业务规则散落在路由层。
5. 再补测试与验收：单元测试覆盖规则，集成测试覆盖 API 与任务，必要时补手工验收记录。
6. 最后更新文档与变更说明：任何 API、Prompt、评分或数据模型变更都必须同步更新文档与版本信息。

## 完成定义

一个功能完成的标准是：

- 代码已实现
- 单测或集成测试已通过
- 文档已更新
- 配置示例已补齐
- 验收证据已记录

## 响应式开发规范

### 开发流程

1. **设计阶段**：确定页面在不同设备上的布局方案
2. **实现阶段**：
   - 先实现移动端布局（Mobile First）
   - 再逐步添加平板端和桌面端样式
   - 使用 CSS 媒体查询或 `useResponsive` 工具
3. **测试阶段**：
   - 在 375px 宽度下测试移动端布局
   - 在 768px 宽度下测试平板端布局
   - 在 1024px+ 宽度下测试桌面端布局

### 代码规范

1. **CSS 媒体查询**：使用移动优先（Mobile First）的写法
   ```css
   /* 默认样式为移动端 */
   .container {
     padding: 16px;
   }
   
   /* 平板端及以上 */
   @media (min-width: 768px) {
     .container {
       padding: 20px;
     }
   }
   
   /* 桌面端及以上 */
   @media (min-width: 1024px) {
     .container {
       padding: 24px;
     }
   }
   ```

2. **响应式工具使用**：
   ```typescript
   import { useResponsive } from '../composables/useResponsive';
   
   const { isMobile, isTablet, isDesktop } = useResponsive();
   
   // 根据设备类型调整行为
   if (isMobile.value) {
     // 移动端特定逻辑
   }
   ```

3. **触摸友好设计**：
   - 按钮最小高度：44px
   - 输入框最小高度：44px
   - 输入框字体大小：16px（防止 iOS 缩放）
   - 可点击元素间距：至少 8px

### 测试要求

1. 使用 Chrome DevTools 模拟不同设备尺寸
2. 在真实移动设备上测试触摸交互
3. 验证所有页面在 375px 到 1920px 宽度下的显示效果
4. 检查表单输入不会触发 iOS 自动缩放
