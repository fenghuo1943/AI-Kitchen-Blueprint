# 数据库数据字典

## 通用规则

表名、字段名使用 `snake_case`；主键为 UUID（或可迁移的字符串 UUID）；时间使用 UTC ISO 8601；金额、重量不使用浮点数。所有业务表包含 `created_at`、`updated_at`，软删除用 `deleted_at`。枚举由代码常量和数据库约束共同维护。

## 核心实体

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| `recipe` | id, title, summary, servings, prep_minutes, cook_minutes, difficulty, status, source_id, revision | 菜谱主表；`status` 为 draft/review/published/archived |
| `recipe_ingredient` | id, recipe_id, ingredient_id, quantity, unit, preparation, optional, sort_order | 单位规范化前保留原文至 `raw_quantity` |
| `recipe_step` | id, recipe_id, step_no, instruction, duration_minutes, image_url | 步骤号在菜谱内唯一 |
| `ingredient` | id, canonical_name, aliases, category, season_months, allergens, nutrition_ref | 规范食材与别名映射的权威表 |
| `recipe_tag` / `tag` | recipe_id, tag_id；name, type | type: cuisine/season/flavor/goal/diet/equipment |
| `inventory_item` | id, household_id, ingredient_id, quantity, unit, expires_at, note | 家庭库存；MVP 默认单一 household |
| `recipe_source` | id, source_type, source_url, author, license, fetched_at, raw_hash | 保存来源、许可和去重依据 |
| `ingestion_job` | id, source_id, status, stage, error_code, result_recipe_id, started_at | 每次采集/导入的可追踪任务 |
| `document_chunk` | id, recipe_id, revision, chunk_type, content_hash, vector_id | 关系库中的向量索引映射，不存向量本体 |
| `recommendation_log` | id, request_hash, filters_json, candidate_ids, rank_version, created_at | 脱敏记录，用于评估，不保存聊天原文 |

## 约束与索引

- `ingredient.canonical_name`、`tag(name,type)` 唯一；别名须映射到一个规范食材。
- `recipe_ingredient(recipe_id, ingredient_id, sort_order)` 唯一；发布菜谱至少有标题、一个食材、一个步骤、来源和许可信息。
- 对 `recipe(status, updated_at)`、`recipe_ingredient(ingredient_id)`、`inventory_item(household_id, expires_at)` 建索引。
- `quantity` 可为空（如“适量”），此时 `unit` 与 `raw_quantity` 必填；推荐匹配不得将空数量当作零。

## 数据质量

菜谱编辑生成新 `revision`，已发布版本不可原地覆写；修订后索引失效直至重建完成。原文、清洗结果和人工修改需保留审计关联。营养、季节和功效是参考数据，必须标注来源和置信状态。
