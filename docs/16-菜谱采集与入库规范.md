# 菜谱采集与入库规范

## 原则与来源

只导入拥有使用许可、授权或可明确合法使用的数据。保存来源 URL/文件、作者、许可、抓取时间、原始内容哈希和采集人。尊重站点条款、robots、频率限制和版权；不绕过登录、付费墙或技术限制。来源不明或许可不清的内容只能留在待处理区，不能发布和索引。

## 状态机

`submitted → fetched → parsed → normalized → validated → review → published`；任一步可转为 `failed`，人工可转 `rejected`。发布后触发索引；索引完成才标识为 `searchable`。任务不可修改原始输入，重跑生成新的处理记录。

## 处理步骤

1. 导入 JSON/CSV/人工录入或经批准的 URL，计算 `raw_hash` 去重。
2. 提取标题、食材、步骤、时间、份量、图片、标签和来源；保留原文与解析置信度。
3. 将食材别名映射为 `ingredient`，单位转为规范单位；无法识别的字段列入人工待审，禁止模型静默猜测。
4. 执行发布校验：必填字段、步骤顺序、合理时长、食材完整性、来源许可、重复菜谱和潜在过敏原。
5. 人工审核差异、补齐标签和季节信息，发布后写入关系库并异步建立向量索引。

## 去重与质量

先以 `raw_hash` 精确去重，再以规范标题、核心食材和步骤相似度找候选重复，合并由人工决定。每次导入提供总数、成功数、待审数、失败数与逐条错误码。失败示例：`SOURCE_LICENSE_UNKNOWN`、`RECIPE_REQUIRED_FIELD_MISSING`、`INGREDIENT_UNRESOLVED`、`DUPLICATE_CANDIDATE`、`INDEX_FAILED`。
