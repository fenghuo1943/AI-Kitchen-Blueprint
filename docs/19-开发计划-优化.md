## 1. 背景与目标

当前 `AI家庭厨房助手`（FastAPI + SQLAlchemy + MariaDB 后端，Vue 3 + Vite + TS 前端）已具备：菜谱 CRUD（软删除）、食材 CRUD（别名）、库存、规则推荐、入库、标签。但相比参考项目 `参考/cook`（PHP 菜谱网站），缺少大量实用的"家庭日常使用"能力。

本计划以 cook 项目为参考，移植/优化以下能力到当前项目：

| # | 能力 | cook 参考实现 | 当前项目现状 |
|---|------|--------------|--------------|
| 1 | 首页菜谱筛选 | 多条件筛选 + 评分排序 + 拼音 | 仅关键词 + 状态筛选，无排序 |
| 2 | 菜单页面（每日菜谱） | 按日菜单 + 日历 + 今日食材/调料聚合 | 无 |
| 3 | 菜谱推荐（发现） | 今日推荐/热门/最新/随机 | 仅库存驱动推荐，无发现页 |
| 4 | 菜谱/食材/分类增改 | 完整编辑表单 + 分类体系 | 菜谱不可编辑食材/步骤，无分类实体 |
| 5 | 回收站 | 软删除 + 恢复 + 彻底删除 | 有软删除字段，无恢复/回收站 |
| 6 | 收藏 | 幂等收藏 + 列表 | 无 |
| 7 | 浏览历史 | upsert 去重 + 最近浏览置顶 | 无 |

## 2. 参考源码分析结论摘要

（详见任务过程中对 `参考/cook` 的分析，核心结论如下）

- **数据模型**：多对多关联（食材/调料/分类/步骤）、`user_daily_recipes` 按日菜单、UNIQUE 去重约束、软删除。
- **搜索评分**（`RecipeSearchRepository::search`）：食材 `exact/any` 匹配、关键词多字段命中打分（title×6 / 分类×2 / 食材×2 / summary×2 / pinyin×1）、`total_score = score + cooked_count×0.5 + is_favorited×2`、排序映射表（score/date/title/cook/random）。
- **推荐**：今日推荐 = `cooked×2 + fav×3 + RAND(CURDATE())`（按日固定随机种子，"当日稳定、每日变化"）+ 随机探索补充；热门/最新/随机。
- **菜单**：`user_daily_recipes(user, recipe, target_date)`；日历月日期查询；当天多道菜食材/调料聚合为"今日采购清单"；瀑布流采用"先分页查 DISTINCT 日期，再取该批日期下菜谱"的两段式查询。
- **历史去重**：`INSERT ... ON DUPLICATE KEY UPDATE viewed_at=NOW()` + UNIQUE(user, recipe)，实现"每菜谱一条、最近浏览置顶"。
- **回收站**：`deleted_at` 软删 + 恢复 + 彻底删除（级联清理）+ 定时清理过期删除记录。

### cook 中的坏点（迁移时规避）

- `view_count / favorite_count` 死列（定义但从不维护）→ 本项目**不新增冗余计数列**，一律实时 JOIN 计算。
- `DELETE /api/history/{recipeId}` 实际清空全部（后端 destroy 无参数 bug）→ 本项目严格按 user+recipe 删单条。
- 菜谱删除/恢复不校验归属 → 本项目按 household 校验归属。
- JWT 密钥硬编码、部分接口无鉴权 → 本项目本期不做登录（见架构决策），后续引入时走环境变量配置。
- 分类 `parent_id` 定义但未使用 → 本项目菜谱分类保留 parent_id（预留），本期按平铺单层使用。

## 5. 后端 API 设计清单

全部路由位于 `/api/v1` 下，与现有分层一致（api → service → repository → models）。

### 5.1 分类管理 `api/categories.py`

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/categories?type=recipe\|ingredient\|seasoning` | 分类列表 |
| POST | `/categories?type=...` | 创建分类（重名 409；recipe 可带 parent_id） |
| PATCH | `/categories/{id}?type=...` | 重命名 |
| DELETE | `/categories/{id}?type=...` | 删除（默认分类 409；被引用时由外键约束保护） |

### 5.2 调料管理 `api/seasonings.py`

CRUD（canonical_name、pinyin 自动生成、category_id）。默认分类保护。

### 5.3 菜谱搜索升级 `api/recipes.py` GET `/recipes`

新增筛选参数（对齐 cook `RecipeSearchRepository`）：

- `ingredients`（食材 ID 逗号分隔）+ `match=exact\|any`（exact=同时包含全部；any=包含任一）
- `category_id`（菜谱分类）
- `q` 关键词 → 命中 title/summary/分类名/食材名/拼音前缀
- `sort=score\|date\|title\|cook\|random` + `order`
- `deleted=true`（回收站）
- 保留现有 `status / difficulty / tags / max_cook_time`
- 列表项新增字段：`is_favorited`、`is_in_today_menu`、`cooked_count`（加入菜单的天数）、`category_ids`、`cover`

评分算法移植：`score = title×6 + 分类名×2 + 食材名×2 + summary×2 + pinyin×1`；`total_score = score + cooked_count×0.5 + is_favorited×2`。

拼音生成：后端统一用 `pypinyin` 在创建/更新菜谱、食材、调料时生成 `pinyin` 列。

### 5.4 菜谱 CRUD 增强 `api/recipes.py`

| 变更 | 说明 |
|------|------|
| POST `/recipes` | 支持 `categories[]`、`seasonings[{id,quantity}]`、`cover` |
| PATCH `/recipes/{id}` | **支持完整编辑**：对食材/步骤/调料/分类/标签"删了重建"（事务包裹），对齐 cook `saveRecipe` |
| GET `/recipes/{id}` | **记录浏览历史**（写 RecipeHistory）+ 返回 `is_favorited`、`categories`、`seasonings`、`is_in_today_menu` |
| POST `/recipes/{id}/restore` | 恢复（回收站） |
| DELETE `/recipes/{id}` | 软删除（入回收站）；`?forever=true` 彻底删除 |
| GET `/recipes?deleted=true` | 回收站列表（复用搜索） |

### 5.5 收藏 `api/favorites.py`

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/favorites?page&page_size` | 收藏列表（JOIN 菜谱，按收藏时间倒序） |
| POST | `/favorites {recipe_id}` | 收藏（幂等 INSERT IGNORE 语义） |
| DELETE | `/favorites/{recipe_id}` | 取消收藏（按 household + recipe） |

### 5.6 浏览历史 `api/history.py`

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/history?page&page_size` | 历史列表（viewed_at 倒序） |
| POST | `/history {recipe_id}` | 手动记录（upsert） |
| DELETE | `/history/{recipe_id}` | **删单条**（修复 cook bug） |
| DELETE | `/history` | 清空全部 |

### 5.7 菜单 `api/menu.py`

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/menu?date=YYYY-MM-DD` | 当天菜单 + `ingList`（今日食材聚合去重）+ `seaList`（今日调料聚合） |
| GET | `/menu?month=YYYY-MM` | 该月有菜单的日期数组（日历红点） |
| GET | `/menu?mode=waterfall&page&page_size` | 按天分组瀑布流（两段式分页） |
| POST | `/menu {recipe_id, date}` | 添加（UNIQUE 防重复） |
| DELETE | `/menu/{recipe_id}?date=...` | 删除某天某菜谱 |

### 5.8 发现/推荐 `api/discover.py`

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/discover?type=today\|hot\|new\|random&limit=6` | 今日推荐 / 热门 / 最新 / 随机 |

- 今日推荐：`score = cooked_count×2 + is_favorited×3 + 按日期固定随机种子`，取 top(n-2) + 随机补 2（探索），当日稳定、每日变化。
- 随机种子：用 Python 按 `date.today()` 做确定性 seed（等价 cook 的 `RAND(CURDATE())`）。

### 5.9 食材升级 `api/ingredients.py`

- 搜索支持 `q` 命中 `canonical_name` 拼音前缀 + `category_id` 筛选（现有 category 字符串筛选保留兼容）。
- 返回 `pinyin`、`category_id`、`category_name`。

## 8. 验收标准

1. 菜谱库页可按 关键词/食材(精确·任一)/分类/难度/状态 组合筛选，并支持 综合/最新/名称(拼音序)/做过次数/随机 排序；输入拼音能搜到中文菜谱。
2. 菜谱可完整新建/编辑（分类、食材、调料、步骤、封面），编辑后食材/步骤关系正确重建。
3. 收藏、取消收藏、收藏列表可用；同一菜谱重复收藏幂等。
4. 打开菜谱详情自动记录浏览历史；重复浏览刷新时间并置顶；可删单条、可清空。
5. 删除菜谱进入回收站；可恢复、可彻底删除（连同关联数据清理）；回收站内仍可搜索筛选。
6. 菜单页可按日查看/添加/移除菜谱，日历显示有菜单的日期红点，瀑布流按天分组分页；当天菜单聚合展示"今日食材/今日调料"。
7. 发现页提供 今日推荐/热门/最新/随机 四类推荐；今日推荐当日稳定、次日变化。
8. 移动端有底部 tabbar，各页面响应式正常。
9. 后端 `pytest tests/ -v` 全绿（含新增模块用例）。

## 9. 风险与注意

- **旧表结构变更**：`create_all` 不改变已存在表，新增字段（Recipe.cover/pinyin、Ingredient.pinyin/category_id）需执行 `002` 迁移；开发库先跑迁移或 drop 重建。
- **食材 category 字符串 → category_id 外键**：现有数据 `category="蔬菜"` 等需要映射到食材分类表；迁移脚本提供 `INSERT ... SELECT DISTINCT` 回填 + 手工核对。
- **pypinyin 依赖**：需加入 `backend/requirements.txt`。
- **性能**：搜索评分涉及多表子查询，数据量大时按 household + deleted 复合索引优化；本期数据量小，先保证正确性。
- **破坏性变更**：`GET /recipes` 响应结构扩展（新增字段为向后兼容追加，不删除现有字段）。
