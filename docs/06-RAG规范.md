# RAG 规范

## 索引范围与流程

仅为 `published` 菜谱建立索引。流程为：发布/修订事件 → 生成稳定文本 → 按语义区块切分 → 嵌入 → 写入 Chroma → 回写 `document_chunk` 映射 → 抽样检索校验。失败任务可幂等重试；删除或归档时同步删除向量。

每条菜谱至少生成：`overview`（标题、简介、标签、时长）、`ingredients`（规范名+原始用量）、`steps`（连续步骤，可按 3～5 步分块）、`tips`（可选）。不得把不同菜谱拼入一个块；块保留 `recipe_id`、`revision`、`chunk_type`、`source_url`、`content_hash` 等元数据。

## 检索

1. 先由结构化条件过滤发布状态、饮食禁忌、设备和时长等硬约束。
2. 使用查询改写（不改变原意）进行向量召回，默认取 Top 20。
3. 以关键词/食材重合、元数据和向量相似度混合重排，默认输出 Top 5～10。
4. 仅把选中块及菜谱 ID、标题、来源传给 LLM；回答附带菜谱标题/来源引用。

未命中或证据不足时，回答“知识库中没有足够依据”，并建议浏览或补充条件；禁止以模型常识补全食材用量、火候或安全结论。

## 质量与运维

记录检索 query（脱敏/哈希）、过滤条件、命中 ID、分数、索引版本和耗时。每次替换嵌入模型或切块策略都建立独立评估集，比较 Recall@K、引用正确率、无依据回答率和延迟；达标后才全量重建。向量库可从关系库及已发布菜谱完全重建。
