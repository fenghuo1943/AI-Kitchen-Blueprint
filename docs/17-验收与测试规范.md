# 验收与测试规范

## MVP 验收场景

| 场景 | 通过条件 |
| --- | --- |
| 菜谱入库 | 合法来源的菜谱经过校验、审核、发布后可浏览；缺字段或许可不明时不得发布 |
| 库存推荐 | 输入库存和约束后，仅返回不冲突的已发布菜谱，并列出命中与缺料 |
| 季节/目标 | 选择月份或目标可影响排序，结果理由能指出对应标签/配置依据 |
| RAG 问答 | 回答能链接到实际菜谱；库中无依据时明确拒答，不虚构步骤或用量 |
| 离线降级 | 关闭云模型/网络后，菜谱浏览、库存与规则推荐仍能完成 |
| 异常任务 | 无效文件、解析失败或索引失败可见具体状态，可安全重试且不重复发布 |

## 质量门槛

- 单元测试覆盖关键规则：食材规范化、过敏/忌口过滤、覆盖率、缺料、状态迁移和输出校验。
- 集成测试覆盖迁移、发布触发索引、任务幂等、API 错误码和模型/向量库不可用降级。
- 固定评估集上：过敏/忌口硬约束零违规；推荐理由与返回菜谱一致；RAG 回答均有证据或明确无依据。具体召回率、延迟目标在有真实数据基线后写入版本化配置。
- 发布前无高危依赖漏洞、无密钥提交、无 P0/P1 未关闭缺陷；关键流程有可复现的验收记录。

## 关键回归测试

1. `库存录入 → 推荐`：新增库存后，推荐结果应包含正确的命中与缺料信息。
2. `草稿 → 审核 → 发布`：菜谱从草稿进入发布流程后，状态和索引应正确更新。
3. `无依据问答`：知识库无足够证据时，回答必须明确拒答而不是猜测。
4. `模型不可用`：关闭模型或网络后，浏览、库存与规则推荐仍可完成。
5. `异常入库`：缺字段、许可不明、重复菜谱或索引失败时，任务状态应清晰可见且可重试。

## 数据验收

抽样检查每批发布菜谱的来源、许可、食材映射、步骤、时间和标签。对于“功效”“营养”“季节”等字段，必须能展示数据来源或标为待验证；任何涉及疾病治疗、婴幼儿或特殊人群的断言均需人工复核并附免责声明。
