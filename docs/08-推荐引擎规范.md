# 推荐引擎规范

## 输入与输出

输入：食材（库存或手填）、人数、月份/地区、最大时长、设备、口味、饮食限制、过敏原、目标标签和是否允许缺料。输出：菜谱摘要、匹配食材、缺少食材、预计时长、约束命中、排序分数及用户可读理由；不输出虚构的营养、疗效或库存数量。

## 三层流程

1. **规则过滤**：仅保留已发布菜谱；剔除过敏原/明确忌口冲突、设备不符、时长超限等硬约束。食材别名统一为规范食材；不确定映射须提示确认。
2. **候选召回与排序**：结构化食材匹配为主，语义/RAG 检索补充相似做法和目标标签。可用初始分数：`0.45 食材覆盖 + 0.20 缺料惩罚 + 0.15 偏好 + 0.10 季节 + 0.10 可执行性`。权重可配置、必须有版本号。
3. **LLM 解释**：在候选集内生成简洁理由、替代建议和澄清问题；不得改变排序、引入候选外菜谱或声称治疗效果。

## 匹配规则

核心食材覆盖率 = 已有核心食材数 / 核心食材总数；可选调料不计入缺料惩罚。默认展示覆盖率 ≥ 0.5 的菜谱，再补充少量“缺 1～2 种关键食材”的结果。保质期临近的库存可加分，但永不覆盖过敏原和饮食限制。

## 可解释性与评估

理由至少包含一个具体依据，例如“命中鸡蛋和番茄，缺葱；约 15 分钟”。记录排序版本和各维度得分。离线评估集覆盖食材别名、冲突忌口、季节、空库存和多目标场景；上线前人工检查 Top 3 的正确性与理由一致性。
