# 愿景与设计原则

## 愿景

让家庭在“冰箱里有什么、今天适合吃什么、怎么做才成功”三个问题上得到可信、可执行且尊重隐私的帮助。系统不是泛美食内容平台，而是围绕家庭一餐决策与执行的知识型工具。

## 设计原则

1. **本地优先**：菜谱、库存、偏好和检索索引默认保存在用户可控环境；调用云模型须显式配置并记录脱敏后的请求。
2. **RAG 优先**：菜谱事实、食材用量、步骤和禁忌须来自已发布知识库；LLM 只负责理解、编排和解释，不得编造菜谱事实。
3. **结构化优先**：推荐过滤、营养估算和库存匹配使用结构化字段；全文/RAG 用于语义召回与问答补充。
4. **安全优先**：过敏原、孕婴/慢病等健康相关内容只作一般饮食提示，不替代医疗建议；信息不足时提示用户核验。
5. **可解释、可追溯**：每个推荐给出命中食材、缺少食材、季节/目标和数据来源；每条菜谱可回溯原始来源与修订记录。
6. **渐进交付**：先保证离线单用户 MVP 可用，再扩展多用户、云同步和智能自动化。
7. **模块化与可测试**：业务规则与 Web、数据库、模型供应商解耦；确定性逻辑必须有自动化测试。
8. **配置优于硬编码**：模型、阈值、权重、地域季节表和敏感词均由版本化配置管理。
9. **响应式设计**：前端页面支持移动端、平板端和桌面端自适应布局，确保在不同设备上都能提供良好的用户体验。
