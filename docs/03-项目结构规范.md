# 项目结构规范

```text
backend/        FastAPI 应用；api、schemas、services、repositories、domain、tasks
frontend/       Vue 应用；views、components、stores、services、types
docs/           本规范与 ADR
data/           本地运行数据（原始导入、SQLite、导出）；不得提交私密数据
docker/         镜像、编排与部署配置
scripts/        可重复执行的运维、导入和初始化脚本
models/         模型配置、下载说明；不提交大模型权重
rag/            切块、嵌入、检索与评估实现
tests/          unit、integration、e2e、fixtures
```

依赖方向：`api → services → domain/repositories`；`tasks → services`；`rag → domain/repositories`。`domain` 不依赖框架、ORM、LLM 或 HTTP。前端 `views → components/stores/services`，不得在组件中复制业务规则。

一个模块只负责一个领域：菜谱、食材、库存、采集、检索、推荐和会话应各自拥有服务与测试。跨领域协调放在应用服务，不得通过互相查询数据库实现。密钥只存在环境变量或未提交的本地配置中。

## 模块职责说明

### 后端
- `backend/api`：HTTP 路由、请求参数校验、响应封装。
- `backend/schemas`：Pydantic / 类型定义，负责接口契约。
- `backend/services`：业务编排，包含推荐、发布、库存、问答等应用服务。
- `backend/repositories`：数据库访问封装，禁止把 SQL 直接散落在 service 层。
- `backend/domain`：纯领域对象、规则和策略，不能依赖 FastAPI、ORM 或模型服务。
- `backend/tasks`：入库、索引重建、异步处理等后台任务。

### 前端
- `frontend/views`：页面级容器，负责页面编排。
- `frontend/components`：基础组件与业务组件。
- `frontend/stores`：Pinia 状态管理，承载页面级状态。
- `frontend/services`：封装 API 调用，统一错误处理。
- `frontend/types`：前端类型定义，与后端 schema 对齐。

### 测试
- `tests/unit`：规则、解析、状态迁移、推荐评分等单元测试。
- `tests/integration`：API、数据库、任务和向量索引的集成测试。
- `tests/e2e`：关键流程测试，如库存录入 → 推荐、草稿 → 发布。

### 数据与配置
- `data/` 仅存放本地样本数据、测试数据和导出文件。
- `models/` 存放模型配置与说明，不提交权重文件。
- `scripts/` 存放可重复执行的迁移、导入、重建索引脚本。
