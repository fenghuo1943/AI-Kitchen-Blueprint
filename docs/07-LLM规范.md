# LLM 规范

## 抽象与路由

实现统一 `LLMProvider`：`generate(messages, response_schema, timeout)`、`embed(texts)`、`health_check()`。提供 Ollama、本地嵌入和可选商业 API 实现；业务层仅依赖抽象接口。配置包括模型名、base URL、温度、最大 token、超时、重试次数、每日预算与是否允许云端。

默认本地模型。商业 API 仅用于用户明确启用的复杂解释、菜谱整理或人工审核辅助，且不得上传库存、用户身份、原始私密会话等不必要数据。

## 输出和降级

能用规则完成的任务不调用 LLM。需要结构化输出时使用 JSON Schema/Pydantic 校验；校验失败最多一次修复重试，仍失败则返回可理解的降级结果。模型超时、不可用或超过预算时，推荐服务返回规则+检索结果及“AI 说明暂不可用”，不能中断核心功能。

## 安全与观测

Prompt 内容视为不可信数据；来源文本不得覆盖系统指令。限制输入长度，清理 HTML/控制字符，日志中不记录密钥、完整个人信息或原始私密内容。记录供应商、模型、模板版本、token、延迟、结果状态和失败原因，用于成本与质量分析。
